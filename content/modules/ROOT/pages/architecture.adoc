= How It Was Deployed
:navtitle: 5. How this Was Deployed

Everything in this environment was built automatically with Ansible, and the demo environment provided a simple RHEL with podman to facilitate the deployment of RHOKP.

== The path a request takes

Your browser never reaches the portal directly. The workload node running
RHOKP has no public address of its own, so everything arrives through the
bastion, and a request makes four hops to get there and back.

. **Browser to an OpenShift Edge Route.** Both addresses on your order page
  are Edge Routes. The HTTPS one terminates TLS at the cluster edge — that is
  what "edge" means here, and it is where encryption stops.
. **Route to Nginx on the bastion.** The Route forwards **plain HTTP**
  onwards: to port 8443 from the HTTPS Route, and to 8080 from the HTTP one.
  Nothing is re-encrypted, which is why the Nginx drop-in proxies HTTP rather
  than HTTPS. Point an HTTPS listener at 8443 and you get a `400`.
. **Nginx to the RHOKP container.** A drop-in at
  `/etc/nginx/proxy.d/rhokp.conf` proxies the request across to port 8080 on
  the workload node. This is the only route in; the node is otherwise
  unreachable.
. **RHOKP to Apache Solr.** Solr runs inside the same container and answers
  from the index baked into the image. No request leaves the environment at
  any point.

== How RHOKP is deployed

RHOKP is not left running as a loose container. RHOKP is installed as a
**systemd service**, so the portal behaves like anything else on the box: it
starts at boot, restarts on its own if it dies, and logs to the journal.

[source,bash,subs="attributes"]
----
sudo systemctl status {portal_service}
sudo journalctl -u {portal_service}
----

What makes that possible is Podman **Quadlet**. Rather than a hand-written
unit file, the container is described in a `.container` file that systemd
reads at boot and turns into a real service, so it gets restart policy,
ordering and journal integration for free:

[source,ini]
----
[Container]
Image=registry.redhat.io/offline-knowledge-portal/rhokp-rhel9:latest
Secret=rhokp-access-key,type=env,target=ACCESS_KEY
PublishPort=0.0.0.0:8080:8080

[Service]
Restart=always
SuccessExitStatus=137 143
----

`Secret=` is the important line. The access key is injected from Podman's
secret store at start time, so it is in neither the unit file nor
`podman inspect` output.

== Where the credentials came from

From you, and nowhere else. The project repository is public and holds no
credentials in any form, not even encrypted ones. So the deploy ran without
them: Ansible installed everything that did not need credentials, left the
portal stopped, and waited for you to supply your own in
xref:credentials.adoc[step 1].

Your access key is then held in a **Podman secret** and injected as
`ACCESS_KEY` only when the container starts, which is why it appears neither
in the unit file nor in `podman inspect` output.

[IMPORTANT]
====
A Podman secret is not encrypted at rest — root on the node can read it. For
production, back it with an external secret driver such as `pass`, or pull
the key from a KMS at container start.
====

== Reproducing it

[source,bash]
----
git clone https://github.com/explicitworkload/rhokp
cd rhokp
scripts/init-secrets.sh          # vaults your pull secret and access key
ansible-playbook playbooks/standalone.yml \
  --vault-password-file playbooks/secrets/vault-password
----

No Galaxy collections to install: the roles use `ansible.builtin` only.
