= Reach the Portal
:navtitle: 1. Reach the Portal

== Open it in a browser

[cols="1,3",options="header"]
|===
|Protocol |URL

|HTTPS (recommended)
|{portal_https_url}

|HTTP
|{portal_http_url}
|===

Both URLs reach the same portal. The HTTPS one is terminated at the cluster
edge and forwarded to the bastion as plain HTTP.

The *Portal* tab on the left of this guide opens the same address.

== Confirm it from the terminal

SSH to the bastion:

[source,bash,subs="attributes"]
----
ssh {ssh_user}@{bastion_public_hostname}
----

Check the public route answers:

[source,bash,subs="attributes"]
----
curl -s -o /dev/null -w '%\{http_code}\n' {portal_https_url}
----

You want `200`.

== Check the node directly

The portal runs on a workload node, not on the bastion. From the bastion:

[source,bash,subs="attributes"]
----
ssh {portal_node}
curl -s -o /dev/null -w '%\{http_code}\n' http://127.0.0.1:8080/
----

If the node answers `200` but the public URL does not, the problem is the
bastion's reverse proxy rather than the portal. See
xref:operating.adoc#proxy[Operate and Troubleshoot].
