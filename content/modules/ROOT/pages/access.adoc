= Reach the Portal
:navtitle: 1. Reach the Portal

== Open it

The portal opens in a **new browser tab** — it cannot be shown in the pane on
the right, because the right-hand pane can only address services on this
Showroom host.

// Rendered by the browser from this page's own hostname. Showroom is served
// at bastion-<guid>.<apps domain> and the portal at app-secure-<guid>.<apps
// domain>, so swapping the leading label gives the right address without
// needing a value the platform never injects into the guide. If the script
// does not run, nothing is inserted and the addresses below still apply.
++++
<p id="rhokp-portal-links"></p>
<script>
(function () {
  try {
    var host = window.location.hostname;
    if (!/^bastion-/.test(host)) { return; }
    var el = document.getElementById('rhokp-portal-links');
    if (!el) { return; }
    var https = 'https://' + host.replace(/^bastion-/, 'app-secure-');
    var http  = 'http://'  + host.replace(/^bastion-/, 'app-');
    el.innerHTML =
      '<a href="' + https + '" target="_blank" rel="noopener noreferrer">' +
      'Open the portal in a new tab</a> &nbsp;<span style="opacity:.7">(' +
      '<a href="' + http + '" target="_blank" rel="noopener noreferrer">' +
      'plain HTTP</a>)</span>';
  } catch (e) { /* leave the static addresses below in place */ }
})();
</script>
++++

Your RHDP order page lists the same addresses under *Through the bastion*:

[cols="1,2",options="header"]
|===
|Protocol |Address

|HTTPS (recommended)
|`app-secure-<guid>.<subdomain>`

|HTTP
|`app-<guid>.<subdomain>`
|===

TLS on the HTTPS address is terminated at the cluster edge and forwarded to
the bastion as plain HTTP.

[NOTE]
====
A cold start takes about 45 seconds while Solr builds its index. A `502` or a
timeout straight after provisioning usually just means it is still starting.
====

== Confirm it from the terminal

Click the **Terminal** tab. You are already on the bastion as
`{ssh_user}`.

The bastion runs Nginx on ports 8080 and 8443 and forwards to the portal, so
you can check the whole path without leaving it:

[source,bash,subs="attributes"]
----
curl -s -o /dev/null -w '%\{http_code}\n' http://localhost:8080/
----

You want `200`.

== Check the node directly

The portal does not run on the bastion — it runs on a workload node, which
has no public address of its own. From the bastion:

[source,bash,subs="attributes"]
----
ssh {portal_node}
curl -s -o /dev/null -w '%\{http_code}\n' http://127.0.0.1:{portal_port}/
----

That tells you which half of the path is at fault:

[cols="1,1,2",options="header"]
|===
|Bastion `:8080` |Node `:8080` |Meaning

|`200`
|`200`
|Everything is working.

|not `200`
|`200`
|The portal is fine; the bastion's reverse proxy is not. See
xref:operating.adoc#proxy[Operate and Troubleshoot].

|not `200`
|not `200`
|The portal itself is down. See xref:operating.adoc[Operate and Troubleshoot].
|===
