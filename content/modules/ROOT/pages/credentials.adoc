= Get Your Credentials
:navtitle: 1. Get Your Credentials

This lab ships **without credentials on purpose**. The automation installs
everything, then stops and waits for you to supply your own. That is also how
you would do it on a customer's disconnected site, so it is worth doing once
by hand.

You need two things, and they are different:

[cols="1,2",options="header"]
|===
|Credential |What it is for

|**Red Hat pull secret**
|Lets the node pull the RHOKP container image from `registry.redhat.io`.
Without it the image cannot be downloaded at all.

|**RHOKP access key**
|A **separate** credential that unlocks the encrypted Knowledgebase content
and the search index. The container reads it as `ACCESS_KEY`. It plays no
part in pulling the image.
|===

They are not two halves of one thing. Anyone with Red Hat registry
credentials — Customer Portal, Red Hat Developer, or a registry service
account — can download and deploy RHOKP. The access key is what unlocks the
Knowledgebase content and search inside it.

[IMPORTANT]
====
No access key and a *wrong* access key are not the same thing.

[cols="1,2",options="header"]
|===
|Access key |What you get

|A valid key
|Everything — Knowledgebase articles and solutions, and working search.

|No key at all
|The portal runs, with a banner across the top of the screen telling you your
access is limited. You can still browse product documentation, product
lifecycle pages and the Security Data API. The encrypted Knowledgebase
content and the search index stay locked.

|A wrong or expired key
|The portal does **not** run. The container exits immediately with
`ERR_002: ACCESS_KEY could not be validated`.
|===

Generate a key in step 2 — the Knowledgebase and its search index are the
point of this lab, and the helper in step 3 asks for one.

The pull secret is not optional either way. Without it the image cannot be
fetched at all, so there is nothing to run, key or no key.
====

Both are tied to **your own Red Hat account**. Nobody else's will do, and
neither is stored in this lab's git repository.

[NOTE]
====
This environment is ephemeral. When your environment expires, the node, the portal
and the Podman secret holding your access key all go away with it. Nothing you
pasted here outlives the lab.
====


== Step 1 — your pull secret

Go to
https://console.redhat.com/openshift/install/pull-secret[console.redhat.com/openshift/install/pull-secret^]
and log in with your Red Hat account.

Use **Copy** or **Download**. Either is fine — it is JSON, and it must contain
an `auths` entry for `registry.redhat.io`. The helper in step 3 checks that
and tells you if it is missing.

== Step 2 — your RHOKP access key

Go to
https://access.redhat.com/offline/access/[access.redhat.com/offline/access^]
— the **RHOKP Key Generator** — and log in with the same account.

Generate your key and copy it. It is a single line of text with no spaces.
Treat it like a password: it is tied to your own entitlement.

== Step 3 — apply them

The portal runs on the workload node, so hop there first. The Terminal tab
opens on the bastion.

[source,bash,subs="attributes"]
----
ssh {portal_node}
----

Then run the helper. It asks for everything it needs:

[source,bash]
----
sudo rhokp-set-credentials
----

Answer its two prompts:

. **Paste your pull secret, then press Enter.** Either form works — the single
  line the *Copy* button gives you, or the formatted JSON from the *Download*
  button, pasted across many lines. The helper reads until the JSON is
  complete, so you do not have to press anything else.
. **Paste your access key, then press Enter.** It is shown on screen on
  purpose, so you can see the paste landed in full.

It validates the pull secret, downloads the image if it is not already on the
node, stores the access key as a Podman secret, starts the portal and waits
for it to answer. Nothing is written to a file you have to clean up afterwards.

[NOTE]
====
The image is about ~7.8 GB, so the download takes a few minutes and prints a
long run of `Copying blob` lines. That is normal — leave it alone.

If your environment was provisioned with the image already pulled, the helper
says `already on this node -- skipping the download` and asks only for the
access key. Then it finishes in seconds.

After the download, a cold start takes about 45 seconds while Solr builds its
index.
====

[TIP]
====
If it rejects your pull secret, the likely cause is a very long single-line
paste that the terminal truncated. Use *Download* instead of *Copy* and paste
the formatted JSON — or save it to a file and point the helper at it:

[source,bash]
----
sudo rhokp-set-credentials -p /path/to/pull-secret.json
----
====

== Step 4 — confirm

[source,bash,subs="attributes"]
----
sudo systemctl is-active {portal_service}
curl -s -o /dev/null -w '%\{http_code}\n' http://127.0.0.1:{portal_port}/
----

You want `active` and `200`.

[cols="2,3",options="header"]
|===
|If you see |Then

|`ERR_002: ACCESS_KEY could not be validated`
|The access key is wrong. Re-copy it from the key generator and run the
helper again.

|`unauthorized` or `401` while pulling
|The pull secret has no valid `registry.redhat.io` entry. Download a fresh
one.

|`That is not a usable pull secret`
|The paste was truncated or incomplete. See the tip in step 3.

|The prompt just sits there after you paste
|The JSON is not complete yet, so the helper is still waiting for the rest of
it. Press *Ctrl-D* to stop it and start again.
|===
