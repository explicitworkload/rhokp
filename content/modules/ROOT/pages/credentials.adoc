= Get Your Credentials
:navtitle: 1. Get Your Credentials

This lab ships **without credentials on purpose**. The automation installs
everything, then stops and waits for you to supply your own. That is also how
you would do it on a customer's disconnected site, so it is worth doing once
by hand.

You need two things, and they are different:

[cols="1,2",options="header"]
|===
|Credential |What it is for

|**Red Hat pull secret**
|Lets the node pull the RHOKP container image from `registry.redhat.io`.
Without it the image cannot be downloaded at all.

|**RHOKP access key**
|Unlocks the portal's content at run time. The container reads it as
`ACCESS_KEY` and exits immediately if it is wrong.
|===

Both are tied to **your own Red Hat account**. Nobody else's will do, and
neither is stored in this lab's git repository.

[TIP]
====
If the portal is already running when you get here, someone has baked
credentials in already — skip to xref:access.adoc[Reach the Portal].
====

== Step 1 — your pull secret

Go to
https://console.redhat.com/openshift/install/pull-secret[console.redhat.com/openshift/install/pull-secret^]
and log in with your Red Hat account.

Use **Copy** or **Download**. Either is fine — it is JSON, and it must contain
an `auths` entry for `registry.redhat.io`. The helper in step 3 checks that
and tells you if it is missing.

== Step 2 — your RHOKP access key

Go to
https://access.redhat.com/offline/access/[access.redhat.com/offline/access^]
— the **RHOKP Key Generator** — and log in with the same account.

Generate your key and copy it. It is a single line of text with no spaces.
Treat it like a password: it is tied to your own entitlement.

== Step 3 — apply them

The portal runs on the workload node, so hop there first. The Terminal tab
opens on the bastion.

[source,bash,subs="attributes"]
----
ssh {portal_node}
----

Write your pull secret to a file. Paste it between the two `EOF` markers and
press Enter — the quoted `'EOF'` keeps the JSON exactly as pasted.

[source,bash]
----
cat > /tmp/pull-secret.json <<'EOF'
<paste your pull secret here>
EOF
----

Then run the helper. It prompts for the access key without echoing it:

[source,bash]
----
sudo rhokp-set-credentials -p /tmp/pull-secret.json
----

It validates the pull secret, pulls the image, stores the access key as a
Podman secret, starts the portal and waits for it to answer. A cold start
takes about 45 seconds while Solr builds its index.

Clean up the plaintext copy when it finishes:

[source,bash]
----
shred -u /tmp/pull-secret.json
----

[NOTE]
====
Running `sudo rhokp-set-credentials` with no arguments prompts for both. Paste
the pull secret and press *Ctrl-D* on a new line to finish, then the access
key.
====

== Step 4 — confirm

[source,bash,subs="attributes"]
----
sudo systemctl is-active {portal_service}
curl -s -o /dev/null -w '%\{http_code}\n' http://127.0.0.1:{portal_port}/
----

You want `active` and `200`.

[cols="2,3",options="header"]
|===
|If you see |Then

|`ERR_002: ACCESS_KEY could not be validated`
|The access key is wrong. Re-copy it from the key generator and run the
helper again.

|`unauthorized` or `401` while pulling
|The pull secret has no valid `registry.redhat.io` entry. Download a fresh
one.

|`no such file` on the paste
|The heredoc did not close. Make sure `EOF` is alone on the last line.
|===
